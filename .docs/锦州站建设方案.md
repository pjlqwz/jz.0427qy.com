## 四、防镜像站的七条措施（本次任务的核心要求）

| # | 措施 | 具体做法 | 判定风险点 |
|---|---|---|---|
| 1 | **正文零复制** | 服务四页参考主站结构、按锦州语境重写；首页文案重写；主站 1466 篇文章与 60 个模板详情页一篇一页都不搬 | 百度对「网址不同、正文大量重复」按镜像/低质处理 |
| 2 | **TDK 全站差异化** | 每个页面 title/description/keywords 独立写，标题带「锦州」地域词，与主站不同文 | 标题和描述都照抄 = 明示重复 |
| 3 | **成品站超市框架形式** | 60 个模板数据复用，但只生成 `/template/` 一个 URL；卡片点击进全屏预览层，「看完整方案」才链主站详情页 | 复制 60 个详情页 = 60 个重复页（营口站 2026-10-22 已验证的做法） |
| 4 | **canonical 自指，不加 hreflang** | 每页 canonical 指向自身；同语言同区域，hreflang 用不上，加了是负优化 | canonical 指主站 = 主动放弃本域排名 |
| 5 | **结构化数据差异化** | ORG JSON-LD：`address` 写盘锦（真实注册地），`areaServed` 写锦州市；`knowsAbout` 同主站 | address 写锦州 = 虚假信息，宁可少写 |
| 6 | **老站 URL 处置** | 老站 628 个 URL 与新站结构完全不同：百度站长平台提交死链 + 仅对确有收录/外链的页在 EdgeOne 配 301 | 老页 404 会累积死链，拖慢新站信任积累 |
| 7 | **内链自然** | 行业页 ↔ 服务页 ↔ 案例 ↔ 资讯互相链；站间只做必要的功能跳转（模板详情、演示站在主站） | 整站一对一镜像链接会暴露站群关系 |

**一句话总结**：栏目和功能「像」主站，正文和 TDK「不像」主站，行业方案页全网独有——
搜索引擎看到的是一个「结构专业、内容为锦州本地而写」的新站，而不是换地名的副本。

## 八、技术方案（直接复用营口站，零新架构）

| 项 | 做法 |
|---|---|
| 代码 | 复制营口站 `web/` 源码，只改 `web/src/config/site.js` 的城市常量（city=锦州、districts=凌河/古塔/太和/凌海/北镇/黑山/义县、geo≈41.10,121.13） |
| 差异化数据 | 新建 `web/src/data/industries.js`（上表 10 个行业）、重写 `news.js`、按锦州语境改各页文案 |
| 共用数据 | `cases.js`（真实案例）、`templates.js`+`tpl-p*.js`（60 模板数据）、`wx-demo.js` + `web/public/wx/` 15 个演示页，原样复制 |
| 构建产物 | Astro build → `web/dist`，deploy 同步到仓库根（EdgeOne 无构建直取根） |
| 工具链 | 营口站 `tools/` 全套照搬：check_urls.py / gen_sitemap.py / deploy.py / push_baidu.py（百度主动推送） |
| 老站 | 一次替换提交换成 Astro 新站，保留 git 历史可回滚（同营口站 32140ad 的做法） |

发布五步（与营口站一致）：
```bash
cd web && node node_modules/astro/astro.js build
python tools/gen_sitemap.py     # 新增页面必跑
python tools/deploy.py          # dry-run 看清单
python tools/deploy.py --apply  # dist → 仓库根
git add -A && git commit && git push origin main   # push 即发布
```
